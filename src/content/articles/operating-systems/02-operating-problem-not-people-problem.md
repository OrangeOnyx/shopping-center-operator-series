# Five Signs a Workflow Has an Operating Problem, Not a People Problem

When work slips, the first explanation is usually a person. Someone forgot, someone was slow, someone needs more training. Sometimes that is right. Often the same slip would happen to anyone placed in that seat, because the workflow depends on memory, unclear handoffs, or rules nobody wrote down. This article gives you five signs that point to the workflow, a scorecard to rate them, and a way to tell the difference before you retrain, replace, or add software.

## Why the distinction matters

The fix for a people problem is coaching, training, a change in role, or sometimes a hard conversation. The fix for an operating problem is a change to the workflow: a clearer trigger, a written rule, a named review point, one home for the information. Apply the wrong fix and the slip returns. Worse, a capable employee takes the blame for a design they did not create, and the business spends trust it needed.

The distinction also matters for AI. An AI tool placed on top of an operating problem tends to make the problem faster, not smaller. If nobody owns a handoff, a tool that drafts the handoff message still leaves the message with no one to receive it.

The five signs below are observable. You do not need a survey to see them. You need a few recent examples and an honest look at the workflow map described in the first article in this series, Before You Choose an AI Tool, Map the Work.

## The five signs

### 1. The same miss happens regardless of who does the work

This is the clearest sign. When a new hire and a ten-year veteran make the same mistake in the same step, the step is the problem. Imagine a twelve-person HVAC service company where maintenance-agreement customers are sometimes billed at standard rates. It happens under every office coordinator the company has employed. The cause is not carelessness. The agreement status lives in a separate spreadsheet that the invoicing screen never shows.

Test question: has this miss happened under at least two different people?

### 2. Work stalls between steps, not within them

Look at where the time goes. If each person completes their part quickly but the job still takes days, the delay lives in the handoffs. A hypothetical regional title office might find that examiners turn around search packages promptly, yet files sit idle because nobody is notified when a package comes back. The work is waiting in an inbox that belongs to no one in particular.

Test question: when a job runs late, is the delay usually inside a step or between two steps?

### 3. The answer depends on one person's memory

"Ask the person who knows" is a workable system until that person is on vacation. If a customer's special terms, a vendor's quirks, or the reason behind a pricing exception live in one head, the workflow has no source of truth. The person holding that knowledge is often the most capable one on the team. The operating problem is that the business made them the only record.

Test question: could someone new complete this step using only written or system records?

### 4. The team re-creates the same information repeatedly

Re-keying a customer's details into three systems. Re-asking a vendor for a certificate the office already received. Rebuilding the same weekly report by hand from the same exports. Each repetition is a small cost and a fresh chance for error. Picture a distributor with three warehouses where each location keeps its own list of customer delivery instructions. The lists drift apart. A driver follows the wrong version, and the conversation turns to the driver.

Test question: is the same piece of information entered or requested more than once in this workflow?

### 5. The same decision gets made from scratch each time

Some decisions should be judgment calls. Many recurring decisions are not: whether a request qualifies for rush handling, when a past-due account goes on hold, which jobs need a second review. If the answer depends on who is asked and how busy they are, the rule has not been written. Different answers to the same question look like inconsistent people. Usually it is a missing rule.

Test question: if two people faced this decision on the same facts, would they reach the same answer?

## The scorecard

Score each sign for one workflow, based on real examples from the last month or two. Keep it plain and quick.

| Sign | 0: Not present | 1: Sometimes | 2: Regularly |
|---|---|---|---|
| Same miss across different people | | | |
| Work stalls between steps | | | |
| Answer depends on one person's memory | | | |
| Same information re-created | | | |
| Same decision made from scratch | | | |

Add the scores. The ranges are a guide for where to look, not a verdict.

- **0 to 3:** The workflow is probably sound. If work is still slipping, a people question such as training, workload, or fit deserves a direct look.
- **4 to 6:** Mixed. Fix the highest-scoring sign first, then watch whether the slips continue.
- **7 to 10:** The workflow is carrying the problem. Map it before any conversation about performance, and before any tool purchase.

Then connect each high score to the workflow map. Each sign tends to show up in a particular column.

| Sign | Where it shows on the workflow map | Typical first fix |
|---|---|---|
| Same miss across people | Information source | Put the needed information where the step happens |
| Stalls between steps | Handoff | Name the receiver and the medium; make the handoff visible |
| One person's memory | Information source, person | Write it into a shared record the step already uses |
| Re-created information | Information source, action | Pick one home for the record; retire the copies |
| Decision from scratch | Decision, review point | Write the rule; name who handles cases outside it |

Some of these fixes invite AI assistance later. Extracting details from incoming documents, comparing a record against a written rule, flagging a handoff nobody has picked up: those are prepare-and-flag jobs a system can help with, with a person reviewing the result. None of them work well until the underlying rule or record exists.

### The view from Arnould Blvd

On The Blvd Shopping Center has 27 demised units across two buildings. A property like that generates recurring work among many parties: the operator, the owner, vendors, and tenants. Several of the five signs are ordinary risks for that kind of asset. Lease terms that one person remembers are sign 3. A maintenance request passed along by phone and never logged is sign 2. The same date typed into several calendars is sign 4.

Command Platform treats these as workflow design choices. Lease terms and critical dates live once and feed every sheet that needs them. Each party sees a scoped view: a vendor sees its work orders and a tenant sees its unit's maintenance items, so a handoff has a visible receiver. The AI concierge prepares and points to the governing document, and people make the decisions. None of this says anyone at the property did anything wrong. It says the workflow now carries what memory used to carry.

## When it really is a people problem

A fair scorecard also tells you when the workflow is not at fault. If a step has a clear trigger, a reliable information source, a written rule, and a named handoff, and one person still misses it while others do not, the question is about that seat. The person may need training, may be carrying too much, or may be in the wrong role. That conversation is easier and fairer once you have ruled out the workflow.

There is also a middle case. A capable person may have built private workarounds, such as a personal spreadsheet or a notebook of customer details, because the workflow did not give them what they needed. Those workarounds are useful evidence. They show you what the system should provide. Treat them as design input, not as a compliance problem.

Scoring the workflow instead of the person also changes the tone of the conversation. People close to the work usually know where it breaks down. When the question is "what does this step need?" rather than "why did you miss it?", they tell you.

## The practical next step

1. Pick one workflow where the same slip has come up more than once in recent months.
2. Gather three to five recent examples and score the five signs, 0 to 2 each, with the people who do the work.
3. For the highest-scoring sign, find its column on your workflow map and write the first fix in one sentence.
4. Hold any performance conversation about that step until the fix has been in place for a few weeks.
5. Collect the private workarounds your team uses for this workflow and read them as a list of what the system is missing.
